제1조 — 설계 철학

본 전략은 한국 증시 장중 단기매매에 특화되며, 세 가지 원칙을 따른다.
첫째, 상승 초입에 진입한다.
둘째, 추세가 살아있으면 보유한다.
셋째, 목표 수익 달성 또는 추세 이탈 시 즉시 청산한다.

모든 매매 판단은 3개의 독립 분석 축(가격 추세, 시장 참여, 자금 흐름)에
모멘텀 가속(MACD)과 거래량 뒷받침(VOL)을 추가한 7조건이
동시에 정렬될 때만 발생하며, 불확실할 때는 거래하지 않는다.
"모르면 안 한다"가 최상위 원칙이다.

2차 필터(Top10)를 통해 조건식 포착 종목 중 최우선 매매 대상만 선별하고,
ST(SuperTrend)가 추세를 유지하는 한 일시적 지표 악화에 흔들리지 않는다.


───────────────────────────────────────────────────────────────
제2조 — 지표 체계
───────────────────────────────────────────────────────────────

2-1. 3축 교차검증 지표

축 1 — 가격 추세:
  SuperTrend(ST_10_3.0)의 Direction 값으로 추세 방향을 판단하고,
  JMA(JMA_14)의 Up/Down 전환으로 모멘텀 전환점을 포착한다.

축 2 — 시장 참여:
  TickIntensity(TICKINT_1)의 정규화 TickSum, MA5, MA20으로
  실시간 매매 참여 강도를 측정한다.
  모든 TickSum 값은 1분 기준으로 정규화한다.
  공식: Normalized_TickSum = Raw_TickSum × (60 / CandleIntervalSec)
  MA5, MA20도 정규화된 값 기반으로 계산한다.
  정규화는 신호 평가 계층에서 수행하며, 지표 원시 출력은 변경하지 않는다.

축 3 — 자금 흐름:
  OBV(OBV_20)의 Direction(OBV vs SMA20 비교)으로
  세력 자금 유입 여부를 판단한다.

2-2. 모멘텀 가속 지표 (신규 — v4.0)

MACD(MACD_7_14_9)의 골든크로스(MACD > Signal 상승돌파)를
매수 조건으로 사용한다. 골든크로스 후 ConfirmBars_MACD(3)봉 이내이며,
MACD > 0, Signal > 0, Histogram > 0 세 값이 모두 양수여야 한다.
데드크로스는 경고 전용(차단 아님)으로 유지한다.

2-3. 거래량 확인 지표 (신규 — v4.0)

Volume(VOL_20)의 현재 거래량이 VOL_MA(20)을 초과해야
매수 조건으로 인정한다. Volume Ratio > 100.

2-4. 보조 지표

RSI(RSI_14)는 모멘텀 하한 필터(기본값 60 이상에서만 매수 허용)로 사용한다.

2-5. 기준봉 틱강도

조건식에 의해 포착된 종목의 최근 10거래일 내 기준봉
(거래량 > 20일 평균 × 2, 양봉)을 식별하고,
해당 일자의 틱봉에서 정규화 TickSum 최대값을
ReferenceCandleTickSum으로 저장한다.
프로파일 A 진입 시 현재 TickSum을 이 값과 비교한다.

2-6. Adaptive 모드

모든 임계값 파라미터는 Fixed(고정)와 Adaptive(적응) 두 모드를 지원한다.
Adaptive 모드에서는 최근 N일 데이터를 기반으로 파라미터를 자동 산출한다.
UI에서 Fixed/Adaptive 전환이 가능하며, 기본값은 Fixed이다.


───────────────────────────────────────────────────────────────
제3조 — 매수 진입 로직
───────────────────────────────────────────────────────────────

3-1. 7조건 AND (v4.0 확장)

다음 7개 조건이 모두 충족되어야 매수 신호가 발생한다.

  조건 1 — ST 상승: SuperTrend Direction = +1 (현재봉 기준)
  조건 2 — JMA 상승 전환: JMA Direction이 Down→Up 전환된 지
            0~ConfirmBars_JMA(2)봉 이내
  조건 3 — TickSum 활성: 정규화 TickSum > 임계값 AND > 정규화 MA5
  조건 4 — OBV 양: OBV Direction = +1 (OBV > SMA20)
  조건 5 — 컨펌 봉수: 조건 1~4가 최근 ConfirmBars(3)봉 이내에
            모두 충족된 이력이 있을 것
  조건 6 — MACD 골든크로스 (신규): MACD가 Signal을 상승 돌파한 지
            ConfirmBars_MACD(3)봉 이내, AND MACD>0, Signal>0, Histogram>0
  조건 7 — 거래량 돌파 (신규): 현재 거래량 > VOL_MA(20)
            (Volume Ratio > 100)

3-2. 추가 필터

RSI >= RSI_MomentumLower(60)를 추가 확인한다.

3-3. 차단 조건 (하나라도 해당하면 매수 불가)

  - 현재 보유 종목 수 >= MaxPositionCount(5)
  - 해당 종목 이미 보유 중
  - 쿨다운 시간 내 (CooldownSec 300초)
  - 현재 시각이 TradingStartTime(09:05) 이전 또는 NoNewBuyAfter(14:30) 이후
  - 위험 필터(제8조) 중 Block 모드 필터에 의해 차단됨
  - 동적 제외(제10조) 대상 종목
  - 손익비 사전 계산(제5조) 미달
  - Top10 필터(제21조) 미선정 종목

3-4. 프로파일별 차이

  프로파일 A(기준봉 돌파형): 기준봉 필수, 현재가 > ReferenceCandleHigh,
    TickSum 기준 = ReferenceCandleTickSum × RatioMin(0.8), 운영 09:05~11:30
  프로파일 B(모멘텀 추종형): 기준봉 불필요,
    TickSum 기준 = Fixed 5.0 또는 당일 최고 TickSum × DayMaxRatio(0.6),
    운영 09:05~14:30


───────────────────────────────────────────────────────────────
제4조 — 청산 로직 (v4.0 전면 재작성)
───────────────────────────────────────────────────────────────

청산은 아래 우선순위 순서로 평가하며, 상위 조건 충족 시 하위는 평가하지 않는다.

4-0. ST 보호 원칙 (핵심 — v4.0 신규)

  ST Direction = +1인 동안에는 P4, P5를 억제한다.
  JMA 일시 하락, OBV 하락, TickSum 약화만으로는 청산하지 않는다.
  청산은 오직 P0, P1, P2, P3(ST -1일 때), P6, P7, P8에 의해서만 발생한다.
  근거: 씨에스윈드, 오르비텍, 엘케이전자 실전 검증 (v4.0)

P0 — 매수 직후 보호 (Grace Period, 신규)
  매수 후 최초 GracePeriod_Bars(5)봉 동안:
  - JMA, TickSum, OBV 중 GracePeriod_ExitConditions(2)개 이상 악화 시 즉시 청산
  - 수익이 한 번도 MinProfitInGrace(0.5%) 이상 된 적 없으면 즉시 청산
  Grace Period 경과 후 정상 ST 보호 규칙으로 전환

P1 — ST 적색 전환
  ST Direction +1 → -1 전환 시 전량 시장가 청산

P2 — VI 근접 청산 (신규)
  수익률 >= 5% AND 가격이 상한가의 90% 이상(VI 임박) 시 전량 청산
  근거: HLB이노베이션, 오르비텍 실전 검증

P3 — 목표수익 + 추세 판단
  수익률 >= TakeProfitRate(5%) AND ST = -1 → 전량 익절
  수익률 >= TakeProfitRate(5%) AND ST = +1 → 트레일링 모드 전환
    (고점 갱신 시 트레일링 기준 갱신)

P4 — JMA 하락 + TickSum 약화 (ST 보호 적용)
  ST = -1일 때만 적용. ST +1이면 이 조건 억제.
  JMA Direction = Down AND 정규화 |TickSum| < 임계값이면:
    수익 중 → 보유량 50% 트레일링 매도
    손실 중 → 전량 시장가 청산

P5 — OBV 하락 (ST 보호 적용)
  ST = -1일 때만 적용. ST +1이면 이 조건 억제.
  OBV Direction = -1 전환 시 보유량 50% 분할 청산

P6 — 손절
  평가 수익률 <= StopLossRate(-3%) 이면 전량 시장가 청산
  (ST 상태 무관, 항상 적용)

P7 — 트레일링 스톱
  EnableTrailingStop = True이고,
  매수 후 고점(HighSinceBuy) 대비 하락률 <= TrailingStopRate(-1.5%)이면
  전량 청산.
  추가: 고점 미갱신 MaxHoldWithoutNewHigh(30)봉 초과 시
  TrailingStopRate를 TightenedTrailingRate(-0.8%)로 강화

P8 — 강제 청산
  현재 시각 >= ForceCloseTime(15:15) 이면 전 보유 종목 시장가 청산


───────────────────────────────────────────────────────────────
제5조 — 손익비 사전 계산
───────────────────────────────────────────────────────────────

매수 신호 발생 시 실제 주문 전에 예상 손익비를 계산한다.
왕복 비용 = BuyCommissionRate(0.015%) + SellCommissionRate(0.015%)
           + TransactionTaxRate(0.20%) + EstimatedSlippage(0.3%)
         = 약 0.53%
순목표수익 = TakeProfitRate - 왕복비용
순예상손실 = |StopLossRate| + 왕복비용
손익비 = 순목표수익 / 순예상손실
MinRiskReward(1.2) 미만이면 매수 차단.


───────────────────────────────────────────────────────────────
제6조 — 주문 방식
───────────────────────────────────────────────────────────────

매수: LimitBestBid(최우선 매도호가 지정가) 기본
매도: Market(시장가) 기본
수량: Floor(총자산 × PositionSizeRate / 현재가)
스프레드: MaxSpreadRate(0.5%) 초과 시 주문 보류

───────────────────────────────────────────────────────────────
제8조 — 위험 필터
───────────────────────────────────────────────────────────────

각 필터는 Off/Observe/Block 3단계 모드로 운영된다.

카테고리 A — 가격 이상:
  A1 갭상승 > 8% (관찰 10분 후 판단)
  A2 가짜 돌파 (ST +1 전환 후 3봉 내 재이탈)
  A3 VI 근접 (상한 > 9%, 하한 > 5%)
  A4 장 시작 5분 변동성 (09:00~09:05 변동률 > 5%)
  A5 전일 대비 20% 이상 상승
  A6 스프레드 > MaxSpreadRate
  A7 손익비 < MinRiskReward
  A8 RSI < RSI_MomentumLower

카테고리 B — 유동성 이상:
  B1 거래대금 < 10억 원
  B2 10시 기준 누적 거래대금 < 3억 원
  B3 5일 평균 거래대금 < 5억 원

카테고리 C — 추세 이상:
  C1 MACD 데드크로스 (경고만, Block 불가)
  C2 연속 60봉 ST Direction != +1
  C3 VI 발동 후 5분 내 미회복

카테고리 D — 시간 이상:
  D1 장 시작 전 (09:05 이전)
  D2 장 마감 접근 (14:30 이후)

필터 엔진은 독립 모듈로 구현하며, ITradeFilter 인터페이스
(Id, Category, Mode, Evaluate)를 통해 각 필터가 등록된다.
FilterEngine.EvaluateAll은 순차 실행하되 Block 필터가 하나라도
발동하면 즉시 중단하고 차단 사유를 반환한다.


───────────────────────────────────────────────────────────────
제9조 — 필터 검증 프로세스 (3단계)
───────────────────────────────────────────────────────────────

1단계 등록: 새 필터를 Off 모드로 등록하고 코드 작성
2단계 관찰: Observe 모드로 최소 20거래일 로그 수집,
           발동 빈도/오탐율/누락율 측정
3단계 실전: 오탐율 < 30%, 누락율 < 10% 충족 시 Block 전환.
           미달 시 파라미터 조정 또는 Off 복귀.


───────────────────────────────────────────────────────────────
제10조 — 종목 풀 관리 (동적 제외)
───────────────────────────────────────────────────────────────

10-1. 정적 제외 (ANALYZING 단계)
  S1: 일봉 종가 < 200일 이평 (장기 하락 추세)
  S2: 5일 평균 거래대금 < 5억 원 (극단적 저유동성)
  (관리종목/투자경고 등은 Kiwoom 조건식에서 이미 제외)

10-2. 동적 제외 (READY 이후)
  D1x: 현재가 전일 대비 20% 이상 상승
  D2x: 장 시작 30분 평균 정규화 TickSum < 2.0
  D3x: 연속 60봉 ST Direction != +1
  D4x: 10시 기준 누적 거래대금 < 3억 원
  D5x: VI 발동 후 5분 내 미회복

10-3. 제외 규칙
  보유 중인 종목은 절대 제외하지 않는다.
  제외 종목은 EXCLUDED 상태로 전환, 틱 구독 해지, 지표 중단.
  제외 필터도 3단계 검증(제9조) 적용.


───────────────────────────────────────────────────────────────
제11조 — 함정 패턴 카탈로그
───────────────────────────────────────────────────────────────

운영 중 발견되는 함정 패턴을 카탈로그로 관리하며,
각 패턴은 제8조 필터와 매핑된다.
새 함정 패턴 발견 시 필터 추가 후 제9조 검증 프로세스를 거친다.


───────────────────────────────────────────────────────────────
제12조 — 실시간 DB 편성 (장중 파이프라인)
───────────────────────────────────────────────────────────────

12-1. 장 시작 후 Kiwoom 조건식이 포착하는 종목 대상으로 즉시 DB 편성.

12-2. 조건식 기준: 시가총액 1,000억~5조, 1분 거래대금 >= 500만 원,
     1분 상승률 >= 1%, 일봉 거래대금 >= 500,
     일봉/주봉 단기이평 >= 장기이평.

12-3. 상태 머신:
     DETECTED → DOWNLOADING → ANALYZING → READY → TRADING → CLOSED
     정적/동적 제외 시 → EXCLUDED

12-4. DOWNLOADING: 일봉 60일, 1분봉 5일, 30틱봉 2일.
     CybosClient + ResearchDB 듀얼 채널 병렬 호출 (Task.WhenAll).
     병렬 최대 3종목. DETECTED→READY 약 3~8초.

12-5. ANALYZING: 정적 제외 검사, 기준봉 식별,
     ReferenceCandleTickSum 산출, Adaptive 파라미터 계산.


───────────────────────────────────────────────────────────────
제13조 — 시스템 아키텍처 (3계층 파이프라인)
───────────────────────────────────────────────────────────────

13-1. Data Layer (스레드풀)
  틱 수신 → CandleBuilder → 캔들 완성 시 IndicatorManager
  (7개 지표 UpdateLast) → Decision Layer로 이벤트 전달.
  CandleBuilder는 현재 시간대에 따라 캔들 주기를 자동 전환한다.
  전환 시점에 미완성 봉을 강제 완성시키고 새 주기로 전환한다.

13-2. Decision Layer (별도 스레드, Producer-Consumer 큐)
  SignalEvaluator(7조건 AND + 프로파일 + RSI 필터),
  FilterEngine(위험 필터), ExclusionEngine(동적 제외),
  OrderExecutor(주문 발행).

13-3. UI Layer (표시 전용)
  타이머(200~500ms)로 StateManager 스냅샷을 그리드에 반영.

13-4. StateManager
  ConcurrentDictionary<String, StockState> 기반 단일 진실 소스.

13-5. 성능 목표
  틱 처리 < 5ms, 캔들→지표 < 20ms/종목,
  필터+판정 < 5ms/종목, 50종목 전체 < 200ms.


───────────────────────────────────────────────────────────────
제14조 — 지표 증분 계산 원칙
───────────────────────────────────────────────────────────────

14-1. Batch (Calculate): READY 전환 시 1회만 실행.
14-2. Incremental (UpdateLast): 캔들 완성 시마다 O(1) 계산.
     내부에서 Calculate 호출 금지.
     _stateIndex로 동일 봉/새 봉 구분.
     캔들 주기 전환 시에도 지표 상태(_prev*, _current*)는 유지.

14-3. 수정 필요 지표:
  OBV: 링 버퍼 SMA + _stateIndex 재작성
  RSI: _stateIndex + _avgGain/_avgLoss 이중 보관
  Volume: 링 버퍼 도입

14-4. 검증 테스트:
  A 일관성, B 안정성(10회 반복), C 순차 증분(100봉)


───────────────────────────────────────────────────────────────
제15조 — 전략 프로파일
───────────────────────────────────────────────────────────────

15-1. 프로파일 A — 기준봉 돌파형 (09:05~11:30)
  기준봉 필수. TickSum 기준 = ReferenceCandleTickSum × 0.8.

15-2. 프로파일 B — 모멘텀 추종형 (09:05~14:30)
  기준봉 불필요. TickSum 기준 = Fixed 5.0 또는 당일최고 × 0.6.

15-3. Auto: 기준봉 존재 시 A → 11:30 이후 B 전환. 없으면 B.

제16조 — 금지 사항
───────────────────────────────────────────────────────────────

① 원칙서에 정의되지 않은 매수 조건 추가 금지
② 7조건 중 어느 하나라도 누락한 매수 신호 생성 금지
③ 파라미터 하드코딩 금지
④ 검증(제14조) 없이 지표 코드 수정 후 배포 금지
⑤ 위험 필터 평가 없이 매수 신호 생성 금지
⑥ Block 모드 필터를 무시하는 코드 금지
⑦ 매직 넘버 단독 사용 금지
⑧ UI 스레드에서 지표 계산/신호 판정 금지
⑨ UpdateLast 내부에서 Calculate 호출 금지
⑩ _prev* 상태 필드 외부 직접 수정 금지
⑪ 보유 중 종목 동적 제외 금지
⑫ infra_original 수정 금지
⑬ infra와 infra_original 동시 실행 금지
⑭ ST +1 상태에서 JMA/OBV/TickSum 단독 악화만으로 청산 금지 (v4.0)

제21조 — Top10 필터 (2차 선별, v4.0 신규)
───────────────────────────────────────────────────────────────

21-1. 목적
  조건식으로 포착된 ~100종목 중 실시간 매매 가치가 가장 높은
  Top N종목만 선별하여 시스템 자원을 집중하고 수익 확률을 극대화한다.

21-2. 선별 기준
  (현재 운영 중인 Top10 로직의 구체적 정렬/스코어링 기준을
   사용자 확인 후 기재 예정)

21-3. 운영
  Top10 필터 미선정 종목은 매수 대상에서 제외한다(제3조 3-3).
  Top10 목록은 실시간으로 갱신되며, 순위 변동 시
  신규 편입 종목은 DETECTED 상태부터 시작한다.
  탈락 종목 중 보유 중인 종목은 청산 완료까지 관리를 유지한다.
