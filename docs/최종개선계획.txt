v3.0 | 2026‑03‑18
제1조 — 설계 철학
본 전략은 한국 증시 장중 단기매매에 특화되며, 세 가지 원칙을 따른다. 첫째, 상승 초입에 진입한다. 둘째, 추세가 살아있으면 보유한다. 셋째, 목표 수익 달성 또는 추세 이탈 시 즉시 청산한다. 모든 매매 판단은 3개의 독립 분석 축(가격 추세, 시장 참여, 자금 흐름)이 동시에 정렬될 때만 발생하며, 불확실할 때는 거래하지 않는다. "모르면 안 한다"가 최상위 원칙이다.

제2조 — 지표 체계
2‑1. 3축 교차검증 지표
축 1 — 가격 추세: SuperTrend(ST_10_3.0)의 Direction 값으로 추세 방향을 판단하고, JMA(JMA_14)의 Up/Down 전환으로 모멘텀 전환점을 포착한다.

축 2 — 시장 참여: TickIntensity(TICKINT_1)의 정규화 TickSum, MA5, MA20으로 실시간 매매 참여 강도를 측정한다. 모든 TickSum 값은 1분 기준으로 정규화하며, 정규화 공식은 Normalized_TickSum = Raw_TickSum × (60 / CandleIntervalSec)이다. MA5, MA20도 정규화된 값 기반으로 계산한다. 정규화는 신호 평가 계층에서 수행하며, 지표 자체의 원시 출력은 변경하지 않는다.

축 3 — 자금 흐름: OBV(OBV_20)의 Direction(OBV vs SMA20 비교)으로 세력 자금 유입 여부를 판단한다.

2‑2. 보조 지표
RSI(RSI_14)는 모멘텀 하한 필터(기본값 60 이상에서만 매수 허용)로 사용한다. Volume(VOL_20)은 거래량 확인용이며, MACD(MACD_7_14_9)의 데드크로스는 경고 전용(차단 아님)으로 사용한다.

2‑3. 기준봉 틱강도
조건식에 의해 포착된 종목의 최근 10거래일 내 기준봉(거래량 > 20일 평균 × 2, 양봉)을 식별하고, 해당 일자의 틱봉에서 정규화 TickSum 최대값을 ReferenceCandleTickSum으로 저장한다. 프로파일 A 진입 시 현재 TickSum을 이 값과 비교한다.

2‑4. Adaptive 모드
모든 임계값 파라미터는 Fixed(고정)와 Adaptive(적응) 두 모드를 지원한다. Adaptive 모드에서는 최근 N일 데이터를 기반으로 파라미터를 자동 산출한다. 예시로 TickSum 임계값은 최근 20일 평균 TickSum × 1.2, RSI 하한은 최근 20일 매수 시점 RSI 하위 25% 값, 손절률은 ATR 기반 동적 산출이다. UI에서 Fixed/Adaptive 전환이 가능하며, 기본값은 Fixed이다.

제3조 — 매수 진입 로직
3‑1. 5조건 AND
다음 5개 조건이 모두 충족되어야 매수 신호가 발생한다.

조건 1 — ST 상승: SuperTrend Direction = +1 (현재봉 기준).

조건 2 — JMA 상승 전환: JMA Direction이 Down → Up으로 전환된 지 0~2봉 이내(ConfirmBars_JMA, 기본값 2).

조건 3 — TickSum 활성: 정규화 TickSum > 임계값(Fixed: TICKINT_Threshold 5.0, 또는 Adaptive: 기준봉 틱강도 × RatioMin 0.8) AND 정규화 TickSum > 정규화 MA5.

조건 4 — OBV 양: OBV Direction = +1 (OBV > SMA20).

조건 5 — 컨펌 봉수: 조건 1~4가 최근 ConfirmBars(기본값 3)봉 이내에 모두 충족된 이력이 있을 것.

3‑2. 추가 필터
RSI ≥ RSI_MomentumLower(기본값 60)를 추가 확인한다. 이 조건은 5조건과 별도로 하한 필터 역할을 한다.

3‑3. 차단 조건 (하나라도 해당하면 매수 불가)
현재 보유 종목 수 ≥ MaxPositionCount(5), 해당 종목 이미 보유 중, 쿨다운 시간 내(CooldownSec 300초), 현재 시각이 TradingStartTime(09:05) 이전 또는 NoNewBuyAfter(14:30) 이후, 위험 필터(제8조) 중 Block 모드 필터에 의해 차단됨, 동적 제외(제10조) 대상 종목, 손익비 사전 계산(제5조) 미달.

3‑4. 프로파일별 차이
프로파일 A(기준봉 돌파형)에서는 기준봉이 존재해야 하고 현재가 > ReferenceCandleHigh를 추가 확인하며, TickSum 기준은 기준봉 틱강도 × RatioMin(0.8)을 사용한다. 운영 시간은 09:05~11:30이다. 프로파일 B(모멘텀 추종형)에서는 기준봉이 불필요하고, TickSum 기준은 Fixed 5.0 또는 당일 최고 TickSum × DayMaxRatio(0.6)을 사용한다. 운영 시간은 09:05~14:30이다.

제4조 — 청산 로직
청산은 아래 우선순위 순서로 평가하며, 상위 조건 충족 시 하위는 평가하지 않는다.

우선순위 1 — ST 적색 전환: SuperTrend Direction이 +1 → -1로 바뀌면 전량 시장가 청산.

우선순위 2 — 목표 수익 + JMA 하락: 평가 수익률 ≥ TakeProfitRate(5%) AND JMA Direction = Down이면 전량 익절.

우선순위 3 — JMA 하락 + TickSum 약화: JMA Direction = Down AND 정규화 |TickSum| < 임계값이면, 수익 중인 경우 보유량의 50%를 트레일링 매도하고 손실 중인 경우 전량 시장가 청산.

우선순위 4 — OBV 하락: OBV Direction = -1로 전환 시 보유량의 50%를 분할 청산.

우선순위 5 — 손절: 평가 수익률 ≤ StopLossRate(-3%)이면 전량 시장가 청산.

우선순위 6 — 익절: 평가 수익률 ≥ TakeProfitRate(5%)이면 전량 청산.

우선순위 7 — 트레일링 스톱: EnableTrailingStop = True이고, 매수 후 고점(HighSinceBuy) 대비 하락률 ≤ TrailingStopRate(-1.5%)이면 전량 청산.

우선순위 8 — 강제 청산: 현재 시각 ≥ ForceCloseTime(15:15)이면 전 보유 종목 시장가 청산.

제5조 — 손익비 사전 계산
매수 신호 발생 시 실제 주문 전에 예상 손익비를 계산한다. 왕복 비용은 매수 수수료(BuyCommissionRate 0.015%) + 매도 수수료(SellCommissionRate 0.015%) + 거래세(TransactionTaxRate 0.20%) + 예상 슬리피지(EstimatedSlippage 0.3%)로 합산 약 0.53%이다. 순 목표수익은 TakeProfitRate - 왕복비용이며, 순 예상손실은 |StopLossRate| + 왕복비용이다. 손익비 = 순목표수익 / 순예상손실이며, 이 값이 MinRiskReward(1.2) 미만이면 매수를 차단한다.

제6조 — 주문 방식
매수 주문은 LimitBestBid(최우선 매도호가 지정가)를 기본으로 사용한다. 매도 주문은 Market(시장가)을 기본으로 사용한다. 주문 수량은 Floor(총자산 × PositionSizeRate / 현재가)로 계산한다. 호가 스프레드가 MaxSpreadRate(0.5%)를 초과하면 주문을 보류한다.

메인 트리거 그룹: ST_Period = 10, ST_Multiplier = 3.0, JMA_Period = 14, JMA_Phase = 50, JMA_Power = 2, TICKINT_Timeframe = 1(분), TICKINT_Threshold = 5.0, TICKINT_NormalizeToMinute = True, TICKINT_UseReferenceCandle = True, TICKINT_RatioMin = 0.8, OBV_MAPeriod = 20.

캔들/타이밍 그룹: CandleIntervalSec = 10, MinCandlesForSignal = 30, TradingStartTime = 09:05, NoNewBuyAfter = 14:30, ForceCloseTime = 15:15, CooldownSec = 300.

모든 파라미터는 UI에서 동적으로 생성되며, ParamDef 테이블 한 줄 추가로 새 파라미터를 등록한다. JSON 기반 Save/Load를 지원하며, Conservative/Standard/Aggressive 프리셋을 제공한다.

제8조 — 위험 필터
각 필터는 Off/Observe/Block 3단계 모드로 운영된다. Off는 비활성, Observe는 로그만 기록, Block은 매수를 실제 차단한다.

카테고리 A — 가격 이상: A1 갭상승 > 8%(관찰 10분 후 판단), A2 가짜 돌파(ST +1 전환 후 3봉 내 재이탈), A3 VI 근접(상한 > 9%, 하한 > 5%), A4 장 시작 5분 변동성(09:00~09:05 변동률 > 5%), A5 전일 대비 20% 이상 상승, A6 스프레드 > MaxSpreadRate, A7 손익비 < MinRiskReward, A8 RSI < RSI_MomentumLower.

카테고리 B — 유동성 이상: B1 거래대금 < 10억 원, B2 10시 기준 누적 거래대금 < 3억 원, B3 5일 평균 거래대금 < 5억 원.

카테고리 C — 추세 이상: C1 MACD 데드크로스(경고만, Block 불가), C2 연속 60봉 ST Direction ≠ +1, C3 VI 발동 후 5분 내 미회복.

카테고리 D — 시간 이상: D1 장 시작 전(09:05 이전), D2 장 마감 접근(14:30 이후).

필터 엔진은 독립 모듈로 구현하며, ITradeFilter 인터페이스(Id, Category, Mode, Evaluate)를 통해 각 필터가 등록된다. FilterEngine.EvaluateAll은 순차 실행하되 Block 필터가 하나라도 발동하면 즉시 중단하고 차단 사유를 반환한다. 향후 C++ DLL 분리가 가능한 구조로 설계한다.

제9조 — 필터 검증 프로세스 (3단계)
1단계 등록: 새 필터를 Off 모드로 등록하고 코드를 작성한다.

2단계 관찰: Observe 모드로 전환하여 최소 20거래일 간 로그를 수집하고, 필터 발동 빈도·오탐율·누락율을 측정한다.

3단계 실전: 관찰 데이터가 기준(오탐율 < 30%, 누락율 < 10%)을 충족하면 Block 모드로 전환한다. 기준 미달 시 파라미터를 조정하거나 Off로 되돌린다.

제10조 — 종목 풀 관리 (동적 제외)
10‑1. 정적 제외 (ANALYZING 단계, 히스토리 기반)
S1 장기 하락 추세: 일봉 종가가 200일 이동평균선 아래(Exclude_MA_Period = 200).

S2 극단적 저유동성: 최근 5거래일 평균 일일 거래대금 < 5억 원(Exclude_MinAvgDailyAmount = 500,000,000).

Kiwoom 조건식(0150)에서 이미 관리종목, 투자경고/위험, 우선주, 정리매매, 불성실공시기업, ETF, SPAC, ETN 등을 제외하므로 이 항목들은 별도 필터하지 않는다.

10‑2. 동적 제외 (READY 이후, 실시간 기반)
D1x: 현재가 전일 대비 20% 이상 상승(Exclude_MaxDayGain = 20%).

D2x: 장 시작 30분 평균 정규화 TickSum < 2.0(Exclude_MinMorningTickSum = 2.0).

D3x: 연속 60봉(10분) ST Direction ≠ +1(Exclude_ST_DownBars = 60).

D4x: 10시 기준 누적 거래대금 < 3억 원(Exclude_MinAmountBy10AM = 300,000,000).

D5x: VI 발동 후 5분 내 가격 미회복(Exclude_VI_NoRecovery = True).

10‑3. 제외 규칙
보유 중인 종목은 절대 제외하지 않는다. 제외된 종목은 틱 구독 해지·지표 계산 중단하며, 상태를 EXCLUDED로 전환하고 사유를 기록한다. UI에서 회색+취소선으로 표시한다. 제외 필터도 제9조와 동일한 3단계 검증을 적용한다.

제11조 — 함정 패턴 카탈로그
운영 중 발견되는 함정 패턴(거짓 돌파, 갭상승 후 급락, VI 직전 매수, 저유동성 함정 등)을 카탈로그로 관리하며, 각 패턴은 제8조 필터와 매핑된다. 새 함정 패턴 발견 시 필터를 추가하고 제9조 검증 프로세스를 거친다.

제12조 — 실시간 DB 편성 (장중 파이프라인)
12‑1. 운영 방식
장 시작 전 사전 다운로드를 하지 않는다. 장 시작 후 Kiwoom 조건식이 실시간으로 포착하는 종목을 대상으로 즉시 DB를 편성한다.

12‑2. 조건식 기준
시가총액 1,000억~5조, 1분 거래대금 ≥ 500만 원, 1분 상승률 ≥ 1%, 일봉 거래대금 ≥ 500, 일봉/주봉 단기 이평 ≥ 장기 이평.

12‑3. 상태 머신
DETECTED → DOWNLOADING → ANALYZING → READY → TRADING → CLOSED. 추가로 정적/동적 제외 시 EXCLUDED로 전환된다. 09:00~09:05 조건식 가동 및 DOWNLOADING 진행, 09:05 이후 READY 종목만 매매 시작, 14:30 이후 신규 매수 금지, 15:15 전 종목 강제 청산.

12‑4. DB 편성 단계
DOWNLOADING 단계에서 일봉 60일(~1s), 1분봉 5일(~2s), 30틱봉 2일(~3s)을 다운로드한다. CybosClient와 ResearchDB를 듀얼 채널로 병렬 호출하며(Task.WhenAll), DB에 데이터가 있으면 즉시 사용하고 없으면 CybosClient에서 페치 후 DB에 저장한다. 병렬 최대 3종목(MaxParallelDownload), DETECTED → READY 약 3~8초.

12‑5. ANALYZING 단계
다운로드 완료 후 정적 제외(S1, S2) 검사, 기준봉 식별(최근 10일 내 거래량 > 평균×2 양봉), ReferenceCandleTickSum 산출, Adaptive 파라미터 계산(활성화 시)을 수행한다. 통과하면 READY, 미통과하면 EXCLUDED.

제13조 — 시스템 아키텍처 (3계층 파이프라인)
13‑1. Data Layer (스레드풀)
틱 수신 → CandleBuilder(틱→캔들 변환) → 캔들 완성 시 IndicatorManager(7개 지표 UpdateLast) → 이벤트로 Decision Layer에 전달. 틱당은 가격만 갱신하고, 지표는 캔들 완성 시점에만 UpdateLast를 호출한다.

13‑2. Decision Layer (별도 스레드, Producer‑Consumer 큐)
SignalEvaluator(5조건 AND + 프로파일 + RSI 필터), FilterEngine(위험 필터 평가), ExclusionEngine(동적 제외 평가), OrderExecutor(주문 발행). 캔들 완성 이벤트를 큐에서 꺼내 순차 처리한다.

13‑3. UI Layer (표시 전용)
타이머(200~500ms)로 StateManager 스냅샷을 읽어 그리드에 반영한다. UI 스레드에서는 지표 계산·신호 판정을 절대 수행하지 않는다.

13‑4. StateManager
모든 종목 상태를 관리하는 단일 진실 소스(Single Source of Truth). ConcurrentDictionary<String, StockState>로 구현하며, StockState에는 코드, 이름, DataState, 현재가, 호가, 당일시가, 전일종가, 거래량, 기준봉 정보, 지표 최신값(ST Direction, JMA Direction, TickSum, OBV Direction, RSI, MACD, Volume Ratio), 필터 결과 캐시, 포지션 정보, 마지막 신호 등을 포함한다.

13‑5. 성능 목표
틱 처리 지연 < 5ms, 캔들 → 지표 < 20ms/종목, 필터 + 판정 < 5ms/종목, 50종목 전체 사이클 < 200ms, UI 갱신 200~500ms.

제14조 — 지표 증분 계산 원칙
14‑1. Batch 모드 (Calculate)
READY 전환 시점 또는 초기 로드 시 1회만 실행한다. 이후 다시 호출하지 않는다.

14‑2. Incremental 모드 (UpdateLast)
캔들 완성 시점마다 마지막 봉만 O(1)로 계산한다. 내부에서 Calculate를 호출하지 않는다. _stateIndex로 동일 봉 재업데이트와 새 봉 추가를 구분한다. 이전 상태(_prev*)와 현재 상태(_current*)를 분리 보관한다. 상태 불일치(stateIndex mismatch) 발생 시 에러 로그를 남기고 해당 종목의 신호를 차단한다.

14‑3. 지표별 현황 및 조치
SuperTrend, JMA, MACD, TickIntensity는 완전한 증분 계산이 구현되어 있어 수정 불필요이다. RSI는 _stateIndex 추가 및 _avgGain/_avgLoss 이중 보관 수정이 필요하다. OBV는 전면 재작성이 필요하며, 링 버퍼 SMA + _lastOBV + _stateIndex 구조로 변경한다. Volume은 링 버퍼 도입으로 매 업데이트마다 N개 순회를 제거하는 수정이 필요하다.

14‑4. 검증 테스트
A 일관성: 전체 Calculate 결과 vs 마지막 봉만 UpdateLast한 결과가 일치해야 한다.

B 안정성: 동일 봉에 UpdateLast를 10회 반복 호출해도 결과가 동일해야 한다.

C 순차 증분: 초기 batch 후 100봉을 순차 UpdateLast하여 전체 Calculate와 비교해야 한다.

제15조 — 전략 프로파일
15‑1. 프로파일 A — 기준봉 돌파형
운영 시간 09:05~11:30. 기준봉 필수. 추가 조건으로 현재가 > ReferenceCandleHigh. TickSum 기준은 ReferenceCandleTickSum × RatioMin(0.8). 기대수익 높음, 신호 빈도 낮음(1~2회/일).

15‑2. 프로파일 B — 모멘텀 추종형
운영 시간 09:05~14:30. 기준봉 불필요. TickSum 기준은 Fixed 5.0 또는 당일 최고 TickSum × DayMaxRatio(0.6). 기대수익 중간, 신호 빈도 중간(2~4회/일).

15‑3. 프로파일 선택 로직
ProfileMode = Auto일 때, 기준봉이 존재하면 09:05~11:30 프로파일 A 적용 후 11:30 이후 미진입 시 B로 전환(ProfileA_SwitchToB = True). 기준봉이 없으면 09:05~14:30 프로파일 B 적용. 사용자는 설정에서 "A만", "B만", "Auto"를 선택할 수 있다.

15‑4. IStrategyProfile 인터페이스
Name, StartTime, EndTime, Enabled, RequiresReferenceCandle(), GetTickThreshold(), GetAdditionalConditions() 메서드를 정의한다.

시나리오 4: 5조건 충족, RSI 55(<60). → RSI 필터 차단. 매수 보류. PASS.

시나리오 5: 5조건 충족, 이미 5종목 보유. → 차단조건. 매수 X. PASS.

제18조 — 코드 작성 착수 조건

조건 3: 위험 필터(제8조)의 초기 모드(Off/Observe/Block) 확정.

조건 4: 시나리오 검증(제17조)에서 모순 없음 확인.

제20조 — 실험 프로젝트 운영 원칙
20‑1. 새 로직은 현재의 infra 환경 그대로 구현한다. 별도 솔루션·프로젝트 분리를 하지 않는다.

20‑2. 작업 시작 전 infra 폴더를 infra_original로 로컬 복사하여 백업한다. GitHub에는 현재 상태가 이미 동기화되어 있으므로 추가 백업은 불필요하다.

20‑3. 성공 시 infra_original 삭제. 새 로직이 메인이 된다.

20‑4. 실패 시 infra_original을 infra로 이름 변경하고 GitHub에 force push하여 원상복구한다.

20‑5. infra_original은 백업 전용이며 실행·수정하지 않는다.

20‑6. 통합 게이트 기준: 백테스트 ≥ 60거래일, 페이퍼 트레이딩 ≥ 20거래일, 승률 ≥ 50%, 손익비 ≥ 1.2, 최대 연속 손실 ≤ 5회, MDD ≤ 10%, 일평균 신호 1~5회, 슬리피지 실측 < 0.3%. 이 기준을 모두 충족해야 성공으로 판정한다.
